NextPax / Switches — KPI Report

Migration process health · reported bi-weekly to leadership
Reporting period Feb 2026 — baseline

What this is. A bi-weekly health check on the Switches project — moving clients onto Boom from their old system, either via NextPax or via Rentals United (RU) as the channel-manager path. It answers one question for leadership: is our migration process getting better? Each number below tracks one part of that.

⚠️ These are baseline numbers, not yet a live measurement. They're pulled from the current migration dashboard so you can see the format and a realistic starting point. They become exact once every migration issue is logged with the standard labels (client · severity · channel-manager). Read them as "roughly where we stand today," not audited figures.

Headline KPIs

The five numbers we report every two weeks. The colour bar on top shows status against target — green = on/above target, amber = needs watching, red = off target.

Channel-manager path & issue mix

Context for the headline numbers: how many switches went through each path, and what kinds of problems are behind the open issues so we can fix root causes rather than symptoms.

Switches by path

How each completed switch reached Boom. NextPax is the focus of this project; RU (Rentals United) is shown for comparison, Direct = no channel manager. 18 switches to date.

Open issues by category

What the currently-open issues are about. A tall bar means that area breaks often during switches and is worth root-causing (e.g. how data or pricing is mapped over).

Critical & High issues still open

Every serious problem currently unresolved on a switched client — the detail behind the "issues per switch" and "clean-switch rate" numbers above. Each stays here until it's fixed and confirmed with the client.

Escalations to NextPax
